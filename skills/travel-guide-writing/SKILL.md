# 旅行攻略写作

让读者先认识目的地，再理解值得体验的内容，最后获得可执行的旅行信息。以下是此用户确认的攻略编辑标准；明确的新要求优先。

## 开始写作前

先读目标文件、项目约定、现行模板和相邻成稿，确认本次是改简介、补章节还是写整篇。保留现有城市身份、文件路径、元数据和可用结构；设计提案不等于已上线格式。只改简介时，不扩大成整篇重写或新增目的地。

目的地边界要明确：市区、行政市域、县域与旅行区域不能混为一谈。远郊及跨城地点说明实际位置；不同尺度的区域无需硬套城市身份或虚构坐标。

## 城市简介：认识这座城市

简介是进入攻略的门户。用一个自然段，通常 120–180 个字符，最多 200 个字符（计标点、不计空白），保持紧凑，不为凑字数填充内容。

- 交代城市是什么样的地方，选择两三个有辨识度的地理、文化或日常生活特征，形成连贯印象。
- 历史可以占一两句，重点是它怎样留在今天的街区、建筑、饮食或生活中。无需朝代流水账。
- 具体地点可以作为城市特征的例子，避免把简介写成景点名单。使用自然、准确的语言，避免空泛赞美、抽象口号和每城同一套句式。
- 不写停留天数、初访怎样分配时间、路线顺序、取舍理由、交通、门票预约或天气应对。这些内容放回相应章节。
- 不放 GitHub、完整攻略、核查来源等链接，不写维护记录、技术实现或产品功能。事实证据保留在正文对应位置或来源章节。
- 没有亲历依据，不编造感官体验、人物对话或第一人称见闻。

审稿时单独阅读简介：读者是否认识了城市？每个例子是否解释了城市特征？去掉城市名后是否能轻易套给几十座城市？出现行程建议时直接移出简介，不另加解释段落。字数合格不能代替语义审稿。

以下已获用户认可的台北简介展示篇幅和内容边界，不是各城套用的句式：

> 台北坐落在群山环绕的盆地里，繁华街区与山林温泉相距不远。大稻埕的茶行、布铺和老店屋，延续着昔日商贸街区的面貌；万华的庙宇仍是日常信仰的一部分。向东走，信义区的高楼与商场展现出现代都会的另一面。故宫的文物收藏之外，牛肉面馆、街边茶店和夜市也构成了认识台北的线索：传统与现代并存，城市生活丰富而具体。

## 正文：体验与实用信息各归其位

沿用项目当前章节结构，按章节的任务写作，不把每节都写成行程安排。

| 内容 | 写到什么程度 |
|---|---|
| 片区 | 说明空间关系、街区气质和主要体验，让读者建立方位感 |
| 景点 | 解释具体看点、特色和适合的兴趣；比较表承载时长、体力、预约等查阅信息 |
| 美食 | 写当地菜点及饮食文化、在哪里容易接触到；店铺推荐须有依据，不以网红排名代替判断 |
| 行程 | 根据距离、实际开放安排与体力组织路线，留出吃饭休息和移动时间；在这里说明时间分配及取舍理由，并提供天气变化或时间不足时的调整 |
| 住宿、交通 | 按区域和真实需求解释差异，写清车站、机场与市中心关系，避免把行政归属当距离 |
| 旅行者须知 | 只纳入影响该目的地体验的亲子、无障碍等信息；入境规则按证件与身份区分适用条件 |
| 来源 | 保存支撑事实的直接链接、核查日期和必要的不确定性，不让来源说明侵入简介 |

叙述先让人理解，表格便于比较。仅在空间关系、路线或选择确实更清楚时使用图示，不给短简介加图，也不为满足图数重复正文。普通城市攻略无需套研究报告的篇章结构。

## 研究与核查

以旅游主管部门、场馆、交通运营商及主管机关等一手来源为主。价格、开放、预约、交通、施工、入境条件等易变事实须核查当前资料；记录实际核查日期，不用统一日期掩盖未研究条目。重要规则说明适用范围，区分常规安排与临时措施。查不到时明确缺口，不猜测。

稳定的历史文化事实同样要有可靠依据。改写已有已核查材料可以复用其证据，新增事实补查来源。原创组织文字，不照搬旅行书或官网长段落，不暗示具有亲历经验。

## 交付审校

逐篇独立审读简介，检查字数、城市辨识度和内容边界；批量工作也不能只验模板。检查正文地点归属、路线可行性、来源与当前元数据。按项目验证方式检查构建后的摘要与阅读页面，确保旧内容和新内容遵守同一规则，简介旁没有额外注入的仓库链接。

技能不授予提交、推送或发布权限；遵守当前项目与用户已经给出的授权。汇报实际改动和验证结果，区分已完成与后续覆盖计划。
